## Where the raw route wins

Two real rows, both honest:

- **Question 1 (exact-name lookup).** A single `grep -rn "class GuardSuspension"` is one call and
  correct. `search_index` is also one call and correct, but it's a ranked-search tool doing a job a
  literal grep does natively — this is the row the protocol explicitly predicts as a near-tie-or-loss
  for the plugin, and it held here.
- **Question 5 (interface implementers), specific to this repo's current shape.** This codebase
  defines exactly one public interface with a real implementer (`IKnowledgeStore` → `KnowledgeStore`),
  so `grep -rn ": IKnowledgeStore"` finds it in one shot. This is not evidence the plugin loses on
  this outcome type generally — it's evidence this specific repo is too small and too interface-light
  right now to stress it. A repo with several interfaces sharing implementer counts, or an interface
  implemented across multiple non-adjacent files, would very plausibly flip this row back to MCP,
  the way question 4 (interface *dispatch*, not just declaration) already did.

No other row favored the raw route. Two rows (4, 6) were not just costlier for raw but produced a
wrong, confidently-stated answer.

## What this does and does not transfer to

Specimen axes: 146 files, 237 types, 2 projects, largest file 2864 (test) / 2544 (production) lines —
a small, single-solution repo.

- **The exact-name-lookup result (question 1, raw wins) transfers directly** to any repo — it's a
  property of the outcome type, not the specimen size. Expect this row to stay a wash-or-raw-win
  regardless of repo size.
- **The interface-implementer result (question 5) is specimen-fragile and should not be
  generalized.** This repo has essentially no interface surface to stress-test — one interface, one
  implementer. A repo with a real plugin/strategy-pattern interface (several implementers, possibly
  across different projects or namespaces) would very likely flip this row to an MCP win, on both
  correctness (raw grep patterns for `: IFoo` miss implementers via `IFoo, IBar` multi-interface
  lists, or classes implementing through an intermediate abstract base) and cost.
- **The dispatch-blindness findings (questions 4 and 6) are the ones most likely to generalize, not
  shrink, on a larger repo.** Both failures came from the raw agent choosing a search pattern that was
  reasonable at this repo's size (scope to `src/`; qualify by class name) but too narrow for the real
  call-site shape. A bigger repo with more test files and more sibling classes sharing method names
  only makes a scoped or qualified grep pattern *more* likely to undercount, not less — this repo, at
  146 files, is closer to the favorable end for the raw route than a larger one would be.
- **The large-file-read result (question 3) is a lower bound on the MCP advantage.** At 2544 lines
  this file already forces the raw route into a targeted line-range `Read` rather than the whole file,
  which is the raw agent behaving well, not the naive worst case. A file too large to guess a line
  range for, or a method whose location isn't already known from the question text, would widen this
  gap further; this run's version of the question already handed the raw agent the exact file path,
  which real usage would not always do.
