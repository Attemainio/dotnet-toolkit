## Where the raw route wins

No question in this matrix landed a clear raw-route win. The closest race was Q1 (exact-name lookup):
narrated call count tied 2-for-2, which matches the outcome table's own prediction that this is the
outcome type where the plugin should win "narrowly, or not at all." What kept even this one from
being a wash for MCP is precision, not cost: MCP's line range matched the true declaration span
exactly (including the doc comment) where raw's didn't.

I did not find a genuine raw-route win to report here, and I looked specifically for one per Step 5 —
the honest explanation is that every question in this matrix had a real property (an unindexed name,
a large file, a partial class, dispatch-adjacent or common-name callers) that favored structured
retrieval, so none of them landed in the pure "one grep, one cat, done" zone where raw is genuinely
cheapest. A future run aimed specifically at that zone (see below) would be a fairer test of whether
raw ever wins outright.

## What this does and does not transfer to

- **Repo size**: 148 files / 239 types is a small-to-medium repo. The token and call-count gaps
  measured here (2.4-2.5x) are the gaps *at this size*; they should widen on a larger repo (more
  candidate matches to sift by hand, larger files to fully read) and could narrow or invert on a much
  smaller one, where a single `grep`+`cat` genuinely is the cheapest possible route regardless of
  what tooling exists. Row 1 (exact-name lookup) is the one most likely to flip on a trivially small
  repo.
- **Interface surface**: this repo has very few interfaces (`IKnowledgeStore` was the only clean
  multi-term match), so Q6 couldn't stress multi-implementer dispatch, and none of the outcomes tested
  a genuinely dead/unused private symbol — the survey (`dotnet-explore`) found none in this repo,
  which is itself a data point about this codebase's hygiene, not about either route. Both would need
  a repo with a richer interface hierarchy or some genuine dead code to test properly.
- **Partial classes**: only one genuine multi-file partial type (`SymbolStore`) was found in this
  repo; the result on it (Q4) is a real, not a synthetic, finding, but it's a sample size of one.
